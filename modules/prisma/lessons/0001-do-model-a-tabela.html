Do model à tabela

Você já sabe descrever a forma de um dado com uma interface. Um model do Prisma faz o mesmo, com uma diferença: o banco garante essa forma.

Sua vitória de hoje Olhar para um model do Prisma e dizer qual tabela ele cria: as colunas, o tipo de cada uma, quais aceitam vazio e qual é a chave primária. Depois, escrever seu primeiro model do zero. Tempo: uns 12 minutos.

Sua missão é construir bancos bem estruturados e limpos para seus projetos. Tudo começa aqui, porque um banco limpo é, antes de tudo, um conjunto de tabelas bem desenhadas.

1. Um banco é um conjunto de tabelas

No PostgreSQL, uma tabela é uma coleção nomeada de linhas. Toda linha de uma tabela tem as mesmas colunas, e cada coluna tem um tipo de dado fixo.[PG]

Para quem vem do TypeScript: imagine um User[] em que todo objeto obedece à mesma interface, e o runtime recusa qualquer objeto que não obedeça. É isso que o banco faz. O tipo não some depois de compilar: ele é verificado em cada escrita.

Um detalhe que pega muita gente: o SQL não garante a ordem das linhas numa tabela. Se precisar delas em ordem, peça explicitamente na consulta.[PG]

2. Toda linha precisa de um RG

A chave primária é a coluna (ou o conjunto de colunas) cujo valor identifica cada linha de forma única. No Prisma você a marca com @id. Sem uma chave primária ou um campo único, operações como update e delete falham, porque o Prisma não sabe qual linha alterar.[Prisma]

Existem dois estilos de chave:[Prisma]

  • Chave natural: um valor que já existe no mundo real e não muda, como o código ISO de um país ("BR").
  • Chave substituta (surrogate): um valor gerado só para identificar a linha, como um inteiro que se autoincrementa ou um UUID. É o padrão recomendado para registros que o seu app cria. Se houver um valor natural, como o e-mail, ele vira um campo comum marcado com @unique.

3. Lendo um model

Aqui estão a mesma ideia em TypeScript, no contrato do Prisma e no banco:

TypeScript

interface User {
  id: number
  email: string
  name: string | null
  createdAt: Date
}

contract.prisma

// use prisma-8

model User {
  id        Int      @id @default(autoincrement())
  email     String   @unique
  name      String?
  createdAt DateTime @default(now())
}

Cada linha dentro do model é um campo e segue o formato nome Tipo atributos:[PSL]

TrechoSignificado no banco
model UserCria a tabela "User". Sem @@map, a tabela tem exatamente o nome do model.
Int, String, DateTimeO tipo da coluna. No PostgreSQL, String vira text e DateTime vira timestamptz(3).[Prisma]
? depois do tipoA coluna aceita NULL (sem valor). Sem ?, o valor é obrigatório.
@idChave primária.
@default(...)Valor padrão que o próprio banco preenche quando o insert não informa a coluna. autoincrement() gera 1, 2, 3…; now() grava o instante atual.
@uniqueDuas linhas nunca podem ter o mesmo valor nessa coluna.

Esse model gera, de forma simplificada, esta tabela:

SQL simplificado (o SQL exato fica para a lição de migrations)

CREATE TABLE "User" (
  "id"        integer        PRIMARY KEY,       -- gerado automaticamente
  "email"     text           NOT NULL UNIQUE,
  "name"      text,                            -- sem NOT NULL: aceita NULL
  "createdAt" timestamptz(3) NOT NULL DEFAULT now()
);

Atenção à versão. Esta lição usa o Prisma ORM 8, que é o que npm install prisma instala hoje. O arquivo se chama contract.prisma e precisa começar com // use prisma-8; sem essa linha ele é ignorado.[PSL] Se um tutorial falar em schema.prisma, @updatedAt ou prisma generate, ele é do Prisma 7 ou anterior. 4. Escolhendo o tipo certo

Um banco "limpo" também depende de bons tipos. Duas regras da documentação oficial que evitam bugs clássicos:[Prisma]

  • Identificadores como CEP ou telefone ficam em String: eles podem começar com zero, e um número descartaria esse zero.
  • Dinheiro fica em Int, guardando a menor unidade (centavos). Nunca use Float para dinheiro.

Pratique: quiz

Responda sem rolar para cima: o esforço de lembrar é o que fixa o conteúdo.

1. O que name String? significa na tabela?

  1. a coluna tem valor único
  2. a coluna aceita valor NULL
  3. a coluna recebe valor padrão
  4. a coluna vira chave primária
O ? torna o campo opcional: a coluna aceita NULL. Valor único é @unique, valor padrão é @default e chave primária é @id.

2. Sem @@map, qual é o nome da tabela criada por model BookReview?

  1. "book_review"
  2. "bookreviews"
  3. "BookReviews"
  4. "BookReview"
Sem @@map, a tabela recebe exatamente o nome do model, sem plural e sem snake_case.[PSL]

3. Para que serve o @id?

  1. para identificar cada linha de forma única
  2. para ordenar as linhas na ordem inserida
  3. para gerar automaticamente os tipos do TypeScript
  4. para impedir valores vazios em outras colunas
A chave primária identifica a linha. Ela não define a ordem: o SQL não garante a ordem das linhas.

4. Quem preenche createdAt DateTime @default(now()) quando o insert não informa esse campo?

  1. o seu código em TypeScript
  2. o navegador do usuário final
  3. o próprio banco de dados
  4. o comando de contract emit
@default define um padrão do banco: o PostgreSQL preenche o valor quando o insert omite a coluna.[PSL]

5. Qual tipo usar para um CEP como "01310-100"?

  1. Int
  2. String
  3. Float
  4. BigInt
CEP é um identificador, não uma quantidade. Pode começar com zero e você nunca vai somar CEPs. Use String.

6. Seu app vende livros. Qual tipo usar para o preço?

  1. Float em reais
  2. String em reais
  3. Float em centavos
  4. Int em centavos
A documentação recomenda Int na menor unidade. Float tem erros de arredondamento (em JS, 0.1 + 0.2 !== 0.3), e String impede somar e comparar.

Pratique: escreva seu model

Um projeto pessoal clássico: registrar os livros que você leu. Escreva o model Book com:

  • id: inteiro, chave primária, autoincrementado;
  • title: texto, obrigatório;
  • isbn: texto, obrigatório, sem repetição entre livros;
  • rating: nota inteira, opcional (talvez você ainda não tenha avaliado);
  • finishedAt: data em que terminou, opcional;
  • createdAt: data de cadastro, preenchida automaticamente pelo banco.

Com suas palavras: o que é uma chave primária e por que prefiro uma chave substituta?

É o valor que identifica cada linha de forma única. A chave substituta (inteiro ou UUID gerado) é estável e não depende de dados do mundo real que podem mudar. O valor natural, como o e-mail, fica num campo @unique.

Qual é a diferença entre ? e @default?

? permite que a coluna fique sem valor (NULL). @default faz o banco preencher um valor quando ninguém informa. Um campo pode ser obrigatório e ter default, como o createdAt.
