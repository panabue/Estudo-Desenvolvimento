INSERT e restrições

O que o PostgreSQL faz com cada coluna de um INSERT, e os erros que aparecem. Fontes: Default Values e Constraints.

Coluna não enviada no INSERT

ContratoNo bancoResultado
x Int @default(autoincrement())DEFAULT nextval(...)Próximo número da sequência
x DateTime @default(now())DEFAULT now()Instante do insert
x String?aceita NULL, sem defaultFica NULL
x StringNOT NULL, sem defaultErro 23502

Erros que você vai ver

SQLSTATEMensagemCausa

23505duplicate key value violates unique constraint "T_x_key"Valor repetido em @unique ou @id
22P02invalid input syntax for type integerValor que não converte para o tipo da coluna

No Prisma 8, o código chega em error.sqlState. [Prisma] Lista completa: PostgreSQL Error Codes.

Fatos que pegam

  • Insert que falha não grava nada, nem as colunas válidas.
  • Coluna @unique aceita vários NULLs: dois NULLs nunca são iguais. [PG]
  • Texto vazio '' é um valor, não é NULL.
  • Insert que falha também consome um id da sequência. Buracos no id são normais. [PG]

Quando usar @default

Regra Só quando o banco sabe o valor certo (id, createdAt, estado inicial como "draft"). Se o valor precisa vir do usuário, deixe o campo obrigatório e sem default: um erro na hora é melhor que um dado errado em silêncio.
